# Architecture

Joidy is a four-service Docker Compose application backed by PostgreSQL 16 with pgvector.

```text
┌─────────────────────────── Docker Compose network ──────────────────────────┐
│                                                                             │
│  ┌───────────┐   ┌──────────┐   ┌─────────────┐   ┌─────────┐  ┌──────────┐ │
│  │ frontend  │   │   api    │   │  ai-service │   │ worker  │  │ postgres │ │
│  │ SvelteKit │──▶│  FastAPI │──▶│  FastAPI    │   │ asyncio │  │   16     │ │
│  │   :3000   │   │  :8000   │   │   :8002     │   │  :8001  │  │  :5432   │ │
│  └─────┬─────┘   └────┬─────┘   └─────────────┘   └────┬────┘  │ +pgvector│ │
│        │              │                                │       └─────┬────┘ │
│        │              └────────────────────────────────┴─────────────┘      │
└────────┼────────────────────────────────────────────────────────────────────┘
         │  published to host — BIND_ADDR (default 127.0.0.1)
   :3000 (ui)   :8000 (api)
```

## Services

| Service | Stack | Port | Exposure |
|---------|-------|------|----------|
| `frontend` | SvelteKit 3 + Vite + TypeScript (adapter-node) | 3000 | Published (`BIND_ADDR`) |
| `api` | FastAPI, Python 3.12 | 8000 | Published (`BIND_ADDR`) |
| `ai-service` | FastAPI — 6 providers + OpenAI-compatible | 8002 | **Internal only** |
| `worker` | Python asyncio | 8001 | **Internal only** |
| `postgres` | PostgreSQL 16 + pgvector | 5432 | Internal only |
| `backup` | Sidecar (compose profile, on by default) | — | Internal only |

`ai-service` and `worker` are not reachable from the host — they live on the Compose network. API → ai-service calls authenticate with the `INTERNAL_SECRET` shared secret (`X-Internal-Secret` header); service-to-service API calls use `INTERNAL_API_TOKEN`.

## Worker tasks

The worker runs three asyncio loops:

1. **Vault watcher** — watches `OBSIDIAN_VAULT_PATH`, imports/updates notes, feeds the webhook sync.
2. **Daily writes** — scheduled tasks (backups orchestration helpers, streak maintenance).
3. **Calendar sync** — incremental Google Calendar sync every `CALENDAR_SYNC_INTERVAL` seconds (default 900) using `syncToken`; a 410 response triggers a full re-sync.

## Data flow

- Frontend calls the API with a JWT (`Authorization: Bearer`).
- API persists everything in Postgres; embeddings live in pgvector columns — no separate vector store.
- AI requests flow API → ai-service → provider (Gemini default, or OpenAI/Anthropic/Cohere/Ollama/OpenRouter/any OpenAI-compatible endpoint).
- Gmail arrives via an n8n workflow that upserts into `/emails` with `INTERNAL_API_TOKEN`.
- Obsidian files flow both ways: filesystem watcher imports changes; a webhook endpoint receives pushes from the vault plugin.

## Persistence

- `postgres_data` volume — all application data (notes, goals, achievements, embeddings, calendar cache).
- `data/backups/` — compressed `pg_dump -Fc` dumps, permissions 0600.
- Alembic manages schema migrations (`make migrate`); migrations run automatically on API start.

## Security posture

- Only `frontend`/`api` publish, bound to loopback by default (`BIND_ADDR` to change).
- JWT required on all data/mutation endpoints; OAuth state nonces, SSRF validation for push endpoints, rate limiting with `TRUSTED_PROXIES`, security headers — see [Security](/docs/security).
